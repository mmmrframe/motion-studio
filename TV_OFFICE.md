# Ролик на ТВ в офис

Тип заявки в форме Motion Studio (вкладка **Ролик на ТВ**, прямая ссылка — `…/motion-studio/#tv`).
Устроено по принципу DDoS priglos: заказчик заполняет поля, получается JSON, скрипт AE **меняет только тексты** в готовом шаблоне. Анимация появления и смена сцен уже собраны в проекте.

**Фон** в каждом ролике свой. Его собирает моушн-дизайнер **отдельным треком** по материалам, которые заказчик прикладывает к заявке.

## Шаги формы
1. **Титул** — название продукта и описание.
2. **Что делает продукт** — заголовок сцены и 4 карточки: заголовок и текст.
3. **Преимущества** — общий заголовок, экраны по **2 блока**. Кнопка «＋ Добавить экран (2 блока)» добавляет сцену, нумерация блоков сквозная (01–02, 03–04, 05–06…). Экраны можно переставлять и удалять, минимум один.
4. **Фон и материалы** — файлы (фото, рендеры, KV, PSD/AI/PDF, MP4, ZIP), ссылка (Figma, Яндекс Диск) и описание, что должно быть на фоне. Нужно хотя бы одно из трёх. Если приложена картинка, она стоит фоном в превью.
5. **Отправка** — сводка, контакт, пожелания, JSON.

## Сцены
| Сцена | Что внутри |
|---|---|
| `S01_TITLE` | логотип Solar, название, описание |
| `S02_FEATURES` | заголовок, 4 карточки 2×2 |
| `S03_ADV_01`, `S04_ADV_02`, … | заголовок «Преимущества …», 2 блока: номер, заголовок, текст |

## Выделение в тексте
В проекте текст блока двухцветный: обычный — серый, важное — белый жирный. В форме важное берётся в `*звёздочки*`:
`Записанные сессии компактно упаковываются. *Периоды простоя не требуют дополнительного места.*`
Непарная звёздочка подсвечивается, и дальше форма не пускает. В JSON текст лежит трижды: `text` — без разметки, `rich` — со звёздочками, `segments` — `[{t, b}]`, где `b: true` — выделенный кусок. Из `segments` скрипт AE раскрасит текст по символам.

## Лимиты
| Поле | Макс. знаков (без звёздочек) |
|---|---|
| Название продукта | 30 |
| Описание (титул) | 200 |
| Заголовок сцены | 45 |
| Карточка «Что делает»: заголовок / текст | 50 / 110 |
| Блок преимуществ: заголовок / текст | 60 / 200 |

Кроме лимитов, форма рисует сцену в кадре 1920×1080 и меряет текстовые поля. Если текст не влезает, она пишет, в какой сцене и в каком блоке, и «Дальше» не активна.

## Превью
- **Экран преимуществ** — по скрину проекта: заголовок 92 px, стеклянные карточки 904×695 (x 38 / 978, y 233), номер оранжевый тонкий, заголовок блока жирный белый, текст 43/51 px серый с белым выделением. Шрифт — Onest вместо ONY, размеры подогнаны под ширину строк проекта.
- **Титул и «Что делает продукт»** — в том же стиле, раскладка предварительная. Чтобы сделать их один в один, нужны скрины этих сцен из проекта.
- **Фон** — заглушка (тёплое размытие) или первая приложенная картинка.

## JSON заявки
```json
{
  "type": "tv_office", "version": 2, "format": { "width": 1920, "height": 1080, "fps": 25 },
  "product": "Solar SafeInspect",
  "scenes": [
    { "id": "S01_TITLE", "kind": "title", "title": "…", "description": { "text": "…", "rich": "…", "segments": [ … ] } },
    { "id": "S02_FEATURES", "kind": "features", "heading": "…", "cards": [ { "n": "01", "title": "…", "text": { … } }, … ] },
    { "id": "S03_ADV_01", "kind": "advantages", "heading": "…", "cards": [ { "n": "01", … }, { "n": "02", … } ] }
  ],
  "background": { "files": [ { "name": "kv.jpg", "size": 123, "type": "image/jpeg", "upload": "uploads/…" } ], "link": "https://…", "note": "…" }
}
```
Через пайплайн GitHub заявка приходит задачей с меткой `tv-office`. В описании задачи — список сцен, отдельный раздел «Фон» для дизайнера и JSON. Файлы материалов при отправке с ключом загружаются в R2.

## Дальше
1. XML проекта: имена композиций сцен и текстовых слоёв, как устроено повторение сцены преимуществ.
2. Скрипт `web/ae/tv_office_apply.jsx`: подставляет тексты и выделение, дублирует сцену преимуществ на каждую пару блоков, ставит сцены друг за другом в главной композиции.
3. Превью титула и «Что делает» — один в один по скринам проекта.
